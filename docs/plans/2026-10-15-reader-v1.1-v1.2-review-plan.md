# Reader v1.1 / v1.2 review: step-by-step plan

The working plan from the reader v1.1 / v1.2 review. The review itself is [2026-10-15-reader-v1.1-v1.2-review.md](2026-10-15-reader-v1.1-v1.2-review.md); section numbers in this file refer to it, and ids in square brackets such as [PED-01] refer to its findings register, [2026-10-15-reader-v1.1-v1.2-review-register.md](2026-10-15-reader-v1.1-v1.2-review-register.md). Each step below is one branch and one PR, or one deploy; tick a chunk when it is done.

## How to use this plan

- **One step per session.** A step is one branch and one PR, or one deploy. Most take 0.5–1 session; the estimate is on each step.
- **Tick the chunks.** Each chunk is one action with a clear stopping point. Not all take 15 minutes: S0.1's two chunks do, but S9.3's three fill a whole session, so split a long chunk into 15-minute pieces when you start it. [USER]'s own reading, QA, lessons and question passes are marked as [USER]'s and can run longer. Tick a chunk when it is done, even if the step is not.
- **Ship at the end of each step.** Shipping means the step's PR is merged to main (in M0, the note or file is committed). Only the steps marked "Deploys: yes" put main on the live site. They are the trains: one deploy that carries every step merged since the last one. Every train runs `scripts/deploy.js` from the deploy lane (S0.5), and you read the dry run's deletion list before `--apply`.
- **When a step runs over,** stop at the end of a chunk. Push the branch (never main), write the next chunk at the top of the PR description or leave a `/snapshot`, and pick it up next session. If a step runs a whole session over, use the cut order below. If the same error comes back three times, step back and try another approach.
- **Decisions come first.** "Decide first" names the decision that must be on file in docs/decisions/ before the step starts. Section 8 has the options and recommendations. The decision sessions are S0.2, S9.0, S12.0 and the ruling chunk of S10.2. A step whose decision is missing waits; the next step that needs none goes ahead.
- **Trains wait for decisions too.** A train carries everything merged since the last one, so no train may run while main holds a merged feature whose own train step is waiting on a decision: hold the train, or keep that feature switched off on main until its own train.
- **Port whole files.** Where a step copies code from v1.1 or v1.2, copy whole files at the named commit and cite the commit's SHA (its short id) in the PR. Hand-wiring a page from memory can silently drop one of the rulings, so the 19 pagination tests run after every pager step.

**Capacity.** Supply is about 5.5 sessions before S (1 November 2026), then about one a week, none in a mid-December content-release week, and about 4 over the break. Demand to the spring term (M0–M4) is about 16.5 sessions, with the rating-scale fix in S4.2, so predict-first reaches the term boundary only if S3.3 moves to M5's train and S4.3, the first cut, waits. Demand to a crossover-ready pager (M9) is about 37 sessions: late May 2027 at one session a week, late March at 1.5. By the end of May that is about nine trains at one session a week and up to eleven at 1.5; each costs half a session or more, already counted in the step estimates. Each phase gives both dates.

**Cut order** when a phase runs long: its stretch items first (the compare step, then the counts export), then the PredictThenRate extraction (S4.3), then the filler queue's SF.3–SF.5. Never cut an accessibility blocker (SF.1 and SF.2 among them) or the settings seam.

**Words used in this plan.**

- **Dark:** on the live site, but reachable only through a special link, so no reader's mode changes.
- **Deploy lane:** a second clone of main used only for deploys, whose content matches the server's file for file.
- **Settings seam:** a settings store that saves only what a reader chose, with a version number and a marker of when the profile was created, so a default can change later.
- **readerPolicy.ts:** one small file that holds every rule an open call decides, so a ruling changes one value.
- **Decision session:** a session in which [USER] rules from written briefs; each ruling, or each deferral to a named later session, goes into its own dated, append-only file in docs/decisions/.
- **Announcer:** one hidden region that screen readers read aloud when something changes.
- **e2e:** end-to-end tests that drive a real browser (Playwright).
- **axe:** an automated accessibility checker. A **ratchet** records today's failures and fails on any new one.
- **Mutant:** a bug planted on purpose to see whether the tests catch it.
- **Cherry-pick:** copy one commit onto another branch. **Port:** bring a feature to main this way, or by copying whole files.
- **Fit-to-offer set:** the fixes paged mode needs before anyone may switch it on: print, second clicks on links, progress that follows the pager, the place kept across visits, and an accessible 'Lestrarstilling'.
- **Crossover:** a classroom comparison in which each student reads one section paged and one scrolled, in counterbalanced order.
- **② preview:** efni's whole-book re-inject preview, which is this machine's local content. It is not the live content, and numbers measured on it say "preview content".
